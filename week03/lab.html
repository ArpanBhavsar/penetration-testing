Part 0 — Metasploitable setup

⏱ 25 min
Goal: Get Metasploitable 2 running in VMware on an isolated Host-only network beside Kali, confirm Kali can reach it, snapshot it, and unzip the lab assets. (Your instructor demos this live.)

0.1 Download Metasploitable 2

Download metasploitable-linux-2.0.0.zip (~830 MB) from the official SourceForge page: sourceforge.net/projects/metasploitable/files/Metasploitable2/. Unzip it somewhere permanent (e.g. Documents/VMs/). You get a folder containing Metasploitable.vmx and the .vmdk disk.

Starter
unzip metasploitable-linux-2.0.0.zip -d ~/VMs/
ls ~/VMs/Metasploitable2-Linux/

You should see Metasploitable.vmx, Metasploitable.vmdk (plus .nvram/.vmsd/.vmxf). It is a ready-made VM — there is no installer to run. On Windows/macOS just right-click → Extract All.

0.2 Open it in VMware (I copied it)

In VMware Workstation, Player or Fusion: File → Open (Player: Player → File → Open) and select Metasploitable.vmx. When VMware asks if you moved or copied the VM, choose I copied it so it gets a new UUID/MAC and does not collide with anyone else’s image. Power it on.

First boot can take a minute. The console login prompt is metasploitable login:. If VMware complains about an unsupported virtual hardware version, click Upgrade (or Continue). Prefer completing 0.3 (Host-only) before the first long boot if your UI lets you edit settings while powered off.

0.3 Set BOTH adapters to Host-only

Shut the VM down (or leave it off). In VMware: VM → Settings → Network Adapter (Fusion: Settings → Network Adapter). Set Metasploitable’s adapter to Host-only (Workstation Pro / Fusion: the named Host-only / vmnet1 network). Do the same for your Kali VM. Confirm neither adapter is on NAT or Bridged. Host-only keeps the deliberately vulnerable OS off the Internet and off the college network.

On the host OS, VMware creates a virtual adapter (Windows: VMware Network Adapter VMnet1; Linux: vmnet1; macOS Fusion: vmnet1). That adapter’s address is your <HOST-IP> (normally .1). The subnet it owns is your <SUBNET>. Write both down — you need them for scope_guard.

Never Bridged or NAT for Metasploitable. Bridged would put it on the same LAN as classmates / the college; NAT would still give it outbound Internet. Host-only only.

0.4 Login, get IP, ping from Kali, snapshot

Power Metasploitable on. At the console login with msfadmin / msfadmin. Run ifconfig (or ip a) and note the eth0 IPv4 — that is <MS2-IP>. From a Kali terminal, ping it. When the ping works, take a VMware snapshot named clean-ms2 so you can roll back later.

2.2 Gate targets with scope_guard (--add-scope)

The built-in approved list still has the VirtualBox example 192.168.56.0/24. Your VMware host-only subnet is different, so pass it with --add-scope and exclude your host adapter with --exclude. Both flags are repeatable. Only private lab subnets of /16 or smaller are accepted.

Starter

python3 scope_guard.py targets-week3.txt \
  --add-scope <SUBNET> --exclude <HOST-IP> \
  --emit nmap-targets.txt
cat nmap-targets.txt

Exact flags (substitute yours):

python3 scope_guard.py targets-week3.txt \
  --add-scope 192.168.110.0/24 --exclude 192.168.110.1 \
  --emit nmap-targets.txt

Optional if you have time: scan all 65535 TCP ports. It is slower; keep -T3 and do not raise timing. Skip if the class is short on time.
